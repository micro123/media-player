# 真机安装与基础流程验证

> 本文记录 0.1.0 骨架版本的历史测试。0.2.0 已接入 libmpv，当前播放测试见 [播放测试记录](playback-test.md)。

测试日期：2026-10-07。

## 环境

- 设备：ADB 报告型号 `moto X40`。
- 系统 API 级别：36。
- 应用：`com.tang.player`，版本 `0.1.0`，Debug APK。
- 安装包：`app/build/outputs/apk/debug/app-debug.apk`。
- 方法：ADB 安装、Activity 启动计时、UI Automator 界面层级检查、模拟点击、页面截图及进程日志检查。
- 测试文件：自行生成的 1 秒静音 WAV，单声道、16 kHz、16 bit，共 32,044 字节。

## 结果

| 检查项 | 结果 | 观察 |
| --- | --- | --- |
| APK 安装 | 通过 | `adb install -r` 返回 `Success`，此前设备没有安装该包 |
| 冷启动 | 通过 | `am start -W` 返回 `Status: ok`，本次三次测量为 552、520、551 ms |
| 页面切换 | 通过 | 文件、播放器、设置页均可进入，标题和内容正确 |
| 文件页初始状态 | 通过 | 最近记录为 0，显示“从一个文件开始” |
| 系统文件选择 | 通过 | 从下载目录选择测试 WAV 后，返回播放器页并显示所选文件名 |
| 文件信息显示 | 通过 | 最近记录显示音频类型和 `32 kB` 大小 |
| 播放器布局 | 通过 | 截图检查标题、占位画面、文件名、控制栏、提示和底部导航，无明显遮挡 |
| 未接入内核的状态 | 通过 | 显示“播放功能准备中”，播放与跳转控件为禁用状态 |
| 最近记录持久化 | 通过 | 强制停止应用并重新启动后，测试文件仍在最近记录中 |
| 最近记录去重 | 通过 | 从最近记录再次打开同一文件后，列表仍为 1 条 |
| 取消文件选择 | 通过 | 返回应用后，原有最近记录保持不变 |
| 文件失效提示 | 通过 | 删除测试文件后点击其最近记录，显示“无法读取所选文件，请重新选择。” |
| 清空最近记录 | 通过 | 在确认只有测试记录后清空，列表恢复为空，重启后仍为空 |
| 应用崩溃检查 | 通过 | 检查时设备 crash buffer 中没有 `com.tang.player` 的崩溃记录 |

初次启动日志中出现 EmojiCompat 查找 `com.google.android.gms` 的字体配置提示；未导致应用崩溃，本次文件和界面流程未受影响。

## 清理与边界

- 已删除手机下载目录中的临时测试 WAV 和 UI 层级临时文件。
- 已清除唯一的测试最近记录，没有清除应用数据或操作用户原有媒体文件。
- 应用保持安装，测试结束时停留在文件首页。
- 本次验证覆盖应用骨架的基础流程，没有测试实际音视频播放；libmpv 尚未集成。
- 视频文件及 Surface 重建、屏幕旋转、系统回收后的状态恢复、后台播放和其他 Android 版本不在本次验证范围内。
